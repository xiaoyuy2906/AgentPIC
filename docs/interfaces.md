# Unified contract, version 3.0

`core/src/contracts.ts` is the only editable contract definition. Zod exports JSON Schema and the locked generator produces Python Pydantic models. `schemas/openapi.json` documents all HTTP routes; MCP exposes the same definitions through tools/list. Python's shared base sets generic finite-number/default validation policy only.

## Design input (`DesignSpec`)

A design is data. The engine has no device-specific fields or code paths (ADR-007); `designs/*.json` are examples generated by `designs/templates.ts`.

| Field | Default | Meaning |
|---|---|---|
| `name` | required | Design name, used in GDS cell names |
| `circuit` | required | A flat `Circuit` or a `CircuitHierarchy` of reusable modules |
| `port_order` | required | Every external optical port exactly once; fixes S-matrix row/column order |
| `platform` | `sin` | Illustrative `sin_demo_v1` PDK |
| `wavelength_nm` | 1550 | Sweep centre, 1500–1600 nm |
| `sweep_span_nm` | 40 | Greater than zero, at most 100 nm; the full sweep must lie in 1450–1650 nm |
| `sweep_points` | 201 | Odd integer, 3–10001 |
| `outputs` | all four | Nonempty unique subset of netlist/simulation/gds/verification |
| `layout` | null | Optional `LayoutPlan`; without it no GDS is produced and layout checks are `not_run` |
| `tuning` | null | Optional optical targets over phase variables |
| `measurements` | `[]` | Optional spectral measurements, at most 16 |

These are software support ranges, not calibrated physical validity ranges.

### Circuit primitives

- **Component:** instance name, kind (`ideal_coupler`, `waveguide`, `phase_shifter`), typed ports, optional `length_um`, `coupling_ratio` and `phase_control`. Couplers have ports `o1..o4` and no length; waveguides `o1,o2` and a length; phase shifters `o1,o2` (optical), `e1,e2` (electrical), a length and `phase_control`.
- **Port:** name, `optical` or `electrical` domain, direction (ideal models require `bidirectional`).
- **Connection:** two `{instance, port}` endpoints. Every port occurs exactly once, either in one connection or as an external port.
- **Hierarchy:** `definitions` with primitives, module instances, connections and port aliases; `top` names the root. Flattened names encode source paths without collisions; `instance_paths` maps each flat name back to its path.

`phase_control` holds a commanded optical phase in −4π…+4π rad at the PDK reference wavelength and an `active_length_um` of 20–200 µm. Electrical terminals appear in IR and layout, are excluded from the optical S-matrix, and have no electrical solver. Voltage/power fields are rejected rather than interpreted as phase.

### Layout plan

Instances are addressed by source path: `top_arm` in a flat design, `second/top_arm` inside module `second`.

- **`placements`**: `{x_um, y_um, rotation_deg ∈ {0,90,180,270}}` places the cell origin. With `anchor: {instance, port}` and `port`, the instance is moved so that its `port` lands on the anchor port plus `(x_um, y_um)`. Anchors must be acyclic. Couplers must be placed; a placed waveguide or phase shifter becomes a straight of its `length_um`.
- **`routes`**: a routed waveguide or phase shifter joins the two placed ports its `o1` and `o2` connect to. With `steps`, the path moves from the start port by `dx_um`/`dy_um` (relative), `x_um`/`y_um` (absolute) or `x_from_end_um`/`y_from_end_um` (relative to the end port), then the engine adds at most one corner so the last segment runs along the end port's axis. Without steps, GDSFactory's `route_single` proposes the Manhattan path.
- **`bundles`**: `{routes: [path, ...], separation_um}` routes two or more step-less routes together with GDSFactory's `route_bundle`, keeping their edge-to-edge separation (default 5 µm).

Every backbone, whatever produced it, is checked by one validator (no backwards entry or exit, no reversal, room for each bend), smoothed with circular PDK-radius bends and extruded by the engine, so measured lengths and bend radii always come from the same representation. `layout.json` records which router produced each path (`steps`, `auto` or `bundle`).
- **`constraints`**: `{kind: "length", instance, value_um}` (default tolerance 0.001 µm) and `{kind: "length_difference", a, b, value_um}` (default 0.002 µm), checked against measured centerline lengths.

Actuators sit centred on the longest straight section of a phase shifter's path. The semantic check `layout_plan` reports every unresolved path, double or missing placement, routed coupler, unplaced route end, anchor error or invalid constraint.

### Measurements

`{kind: "resonances", input_port, output_port, min_count}` requires at least `min_count` peaks of |S(output, input)|² whose half-maximum crossings both lie inside the window. Evidence lists resonance wavelengths, half-maximum widths, spacings and ideal-model loaded Q.

## Typed engineering records

- **PDK:** process identifier, layers, geometry rules, assumed indices and supported components. The current PDK is a demonstration declaration, not a foundry integration.
- **EngineeringIR:** version, design ID, the submitted specification, PDK, flat netlist, source `hierarchy` and `instance_paths`, optional `operating_point`, workflow DAG, `layout_resolved`, `length_source` and assumptions.

Schemas reject unknown fields. Semantic validation separately rejects unresolved references, duplicate names, double-used/dangling ports, incompatible domains/directions, disconnected circuits, missing model parameters, PDK violations, invalid task dependencies, port-order mismatches, layout-plan errors and any netlist that differs from the submitted circuit beyond measured lengths and the applied operating point.

## Runtime and backend boundary

The TS Runtime invokes the typed ScientificBackend interface. Run `uv sync --locked` during setup. The adapter executes that prepared environment's Python with `-m agentpic.worker`, writes one JSON request to stdin, reads one JSON response, and validates the returned shape. It never resolves interpreters or synchronizes packages during scientific requests. `UV_PROJECT_ENVIRONMENT` selects a custom environment and must also be passed to any MCP subprocess. No SAX dictionaries or GDSFactory objects cross the adapter boundary.

The workflow is compile → [layout → backannotate] → [tune] → simulate → verify → manifest; bracketed tasks run only when the design declares a layout plan or tuning. State and events persist after transitions. Backend errors fail the task, block dependents and retain partial artifacts. A completed verification task may still report failed checks and cause overall failure. There is no automatic process-crash recovery or resume.

## Results

`RunResult` contains run/design IDs, status, verification status, server-local artifact directory, hashes and optional error. HTTP clients download through the artifact route; MCP uses resource URIs. `VerificationReport` includes per-check pass/fail/not_run, evidence, limitations and literal `foundry_signoff: false`.

`SimulationResult.s_real` and `s_imag` are indexed `[wavelength][output][input]` in `port_order`. `spectrum.csv` lists every wavelength/output/input entry with real, imaginary and power columns.

`manifest.json` and `run.json` are not included in their own hash inventories. Local hashes are an integrity reference, not a signed attestation. Reverification returns a fresh report without altering the original evidence. Version 2.0 artifacts are not accepted as 3.0 runs.

## Target tuning

```json
{
  "targets": [{"input_port":"in0", "output_port":"out0", "wavelength_nm":1550, "power":0.8}],
  "variables": [{"instance_path":["top_arm"], "min_phase_rad":0, "max_phase_rad":6.283185307179586}],
  "power_tolerance": 0.000001,
  "max_evaluations": 128
}
```

Select 1–4 distinct existing phase shifters by source path and 1–16 distinct `(input_port, output_port, wavelength_nm)` targets on external optical ports. Wavelengths must be on the sweep grid; no interpolation is performed. Bounds must be strictly ordered within −4π…+4π and contain the initial setting. Tolerance is an absolute power error in [1e-9, 1e-3], default 1e-6. The hard budget is 1–512 SAX network calls, default 128, including numerical differentiation.

`EngineeringIR.operating_point` is null before optimization and otherwise maps exactly the selected flattened primitive IDs to applied phases. `specification` and `hierarchy` keep the original settings; `pre-tuning-ir.json` preserves the measured state before search; `tuning.json` records status, selected controls, predictions, residual, evaluation count, the complete candidate trace and termination reason.

Optimization uses SciPy `least_squares` with bounded local searches and deterministic starts; it does not prove infeasibility or global optimality. `target_met` requires an evaluated candidate within every tolerance; `budget_exhausted` and `target_not_met` still produce final simulation and verification artifacts with overall `status: failed`. Verification replays every candidate through the independent network-elimination reference.

`POST /v1/simulations` and MCP `simulate_circuit` accept unresolved compiled IR (including tuning) and return `CircuitSimulation`; their `length_source` stays `specification`. For persisted operating points use `verify_run`.
